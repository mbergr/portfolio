**Project:** [jazz-standards-analytics](https://github.com/mbergr/jazz-standards-analytics) — end-to-end pipeline over the jazz standards canon (ingest → model → visualize).
**Status:** Ingestion + staging + marts complete. Dashboard not started.

## Done

- Intermediate views: entity resolution (keep candidates whose normalized track title matches the standard) and deduplication (one recording per standard/artist, earliest release).
- Star-schema marts as tables: `fct_recordings` + `dim_standards`, `dim_artists`, `dim_years`. Surrogate keys via `dbt_utils`.
- Reusable `normalize_title` macro (lowercase, strip parentheticals / suffixes / punctuation).
- 24 tests including fact → dimension `relationships`. `dbt build` → PASS=32, 0 errors.
- Funnel: 703 candidates → 612 resolved (91 false positives dropped) → 548 fact rows. Output is coherent: widest repertoire is Ella Fitzgerald (21 standards), then Billie Holiday (14).

## Decisions

- **Entity resolution = exact normalized-title match** — removes clear false positives ("Summertime Sadness" ≠ "Summertime") at the cost of a few legitimate variants. Precision over recall for a canon analysis.
- **`dim_years`, not a full calendar dimension** — Spotify dates are year-grain, so a day-level date dim would be over-modeling.
- **Materialization** — intermediate as views, marts as physical tables (the serving layer).
- **`dbt_utils`** — first external package, introduced here for surrogate keys.

## Data caveats

- `release_year` is the Spotify *release* date, not the recording date; reissues inflate the "Contemporary" era. It's release-era, not recording-era.
- "Most recorded" is capped at 10 by the ingestion limit (`RECORDINGS_PER_STANDARD`), not a true canon count.
- Exact-match resolution produces some false negatives (e.g. a track that spells an in-title parenthetical inline).
