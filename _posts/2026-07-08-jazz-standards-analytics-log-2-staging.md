## Done

- Initialized the dbt-duckdb project: `dbt_project.yml`, `profiles.yml` pointing at the local DuckDB file.
- Declared `raw.standards` and `raw.recordings` as dbt sources.
- Two staging models, materialized as views: `stg_standards`, `stg_recordings` — rename to a consistent scheme, trim, cast, empty-string-to-null.

- 7 native dbt tests (`not_null`, `unique`, `relationships`). `dbt build` → PASS=9, 0 errors.

## Decisions

- **Staging = views** — recomputed on read, no data duplication. Physical tables are reserved for the marts.
- **No `dbt_utils` yet** — first dbt contact kept dependency-free with native tests only. Surrogate keys and combined-uniqueness are deferred to the marts layer, where they're actually needed.
- **Composer splitting deferred** — the raw layer lost the delimiter between co-writers (an HTML `<br>` collapsed to a space) and names themselves contain spaces, so reliable splitting isn't possible downstream. It needs a scraper fix plus a bridge table, not a staging hack.
